# Apple Silicon 硬件、并发与耗时估算

更新日期：2026-08-02  
适用版本：1.1.5 本地验证候选及其 19 阶段串行流水线

> **重要：除 M1 Max 32GB 一列外，本文所有 M5 Max 和 M3 Ultra 数字均为估算，不是实机测试。**
> 估算只用于选择安全起点，不能作为购买建议、性能承诺或完成时间保证。

## 估算依据

### 已实测基线

本项目目前只有一套可核验的大型真实任务基线：

- Apple M1 Max，10 核 CPU、32 核 GPU、32GB 统一内存；
- 原始素材约 2.2TB，放在单块机械硬盘；索引、模型和派生画面放在内置 SSD；
- 1,543 个有效视频来源、50 张图片、32,618 个可搜索画面；
- 6,051 个 Qwen-VL 高价值画面候选、27 个 OCR 候选；
- 19,257 份搜索文档、6,248 个去重文本向量；
- 已成功完成的 1.1.4 全流程合计约 14 小时 50 分；1.1.5 正在做第二轮真实任务验证。

M1 Max 官方规格为 400GB/s 内存带宽、一个视频解码引擎；本次任务的主要实际并发为：
视频抽帧 5 路、YOLOE/OpenCLIP/Qwen-VL 3 路、人物检测 8 路、OCR 3 路、文本向量 3 路。

当前 32GB 真实运行还观察到过一次 Qwen-VL worker 的 Metal GPU timeout。因此：

- 2 路是长时间无人值守时更保守的 Qwen-VL 起点；
- 3 路是当前性能档，但必须依赖逐项提交、worker 失败可见和自动补位；
- 4 路只是内存估算上限，不应写成已经验证的稳定值。

同规模总时间粗略范围：

- M1 Max 32GB：约 14小时50分（实测完成任务）；
- M5 Max 128GB：约 6–9小时（估算）；
- M3 Ultra 256GB：约 4小时10分–7小时（估算）。

总时间不能只按芯片计算。第 01、03 阶段如果继续使用同一块机械硬盘，磁头寻道和顺序吞吐可能成为主要瓶颈；此时把 FFmpeg 从 8 路提高到 16 路可能更慢。上表第 03 阶段的高并发更适合 SSD、RAID 或多盘分散读取。单块机械硬盘建议 M5 Max 先用 5–6 路、M3 Ultra 先用 6–8 路，再根据实际 MB/s 调整。

## 当前软件上限与实验上限

“内存放得下”不等于“继续增加 worker 会更快”。同一模型的多个进程会争用 GPU、内存带宽、Metal command queue、SQLite writer 和存储吞吐。

| 工作类型 | 1.1.5 当前可配置上限 | 更高硬件实验范围（估算，尚未开放/验证） |
|---|---:|---:|
| Qwen-VL / YOLOE 模型 worker | 8 | M3 Ultra 10–12；必须先修改上限并做压力测试 |
| OpenCLIP worker | 3 | M5 Max 4–6、M3 Ultra 6–8 |
| 文本向量 worker | 自动推荐最多4 | M5 Max 6–8、M3 Ultra 8–12 |
| OCR worker | 当前任务快照决定 | M5 Max 6–8、M3 Ultra 8–12 |
| FFmpeg 抽帧 | 16 | 受解码引擎、编码格式和源盘吞吐共同限制 |
| SQLite 合并/结构/快照阶段 | 1 writer | 保持1；增加 writer 通常不会加速 |

这些实验范围不是建议普通用户直接填写的数值。正式提高软件上限之前，至少要验证：

1. 每个 worker 的峰值统一内存，而不是平均值；
2. 30 分钟以上持续运行无 Metal GPU timeout；
3. swap 不持续增长、内存压力保持绿色；
4. 吞吐量随并发增加，而不是只增加等待和温度；
5. 任一 worker 崩溃后任务可自动补位，已提交项目不会重做；
6. 同一数据分别用 N 路和 N+1 路运行，结果数量与数据库完整性一致。

## 自动配置建议

未来版本应按“任务阶段”而不是只按总内存选择并发：

- **机械硬盘阶段（01、03）**：优先看源盘吞吐和寻道，不追求最大 CPU 并发；
- **轻量视觉模型（05、06、08）**：结合 GPU 核数、内存带宽和每 worker 峰值内存；
- **生成式模型（13、14）**：保留至少 12–24GB 给系统和 Metal，逐级从低并发升档；
- **OCR 与文本向量（15、19）**：可比 Qwen-VL 更积极地提高并发，但仍要限制 SQLite 提交压力；
- **数据库阶段（04、09、11、12、16–18）**：保持单 writer，用批次事务优化，不用堆 worker。

建议应用将每台新硬件的完整运行结果以匿名硬件基准导出，至少记录芯片、内存、阶段、输入量、并发、峰值内存、吞吐、耗时、失败数和存储类型。收集到真实 M5 Max 或 M3 Ultra 数据后，应以实测替换本文对应估算。
