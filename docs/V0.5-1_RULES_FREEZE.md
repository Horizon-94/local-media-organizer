# V0.5-1 Rules Freeze

## Scope

V0.5-1 freezes the rules required before any real V0.5 model work starts:

- unified evidence records;
- deterministic evidence identity and file identity fallback;
- high-value frame selection for future Qwen-VL analysis;
- resource status and concurrency profile rules;
- folder batch processing rules.

This task does not run YOLOE, OCR, Qwen-VL, VAD, Whisper, embedding models, semantic search, or 30GB processing.

## Schema Version

All V0.5-1 rule structures use:

```text
schema_version = "0.5.1"
```

The shared fields `run_id`, `folder_id`, `folder_path`, `source_root`, `source_path`, `media_id`, `schema_version`, `created_at`, and `status` keep the same type and meaning wherever they appear.

## Unified Evidence

The unified evidence schema supports:

- `visual_object`
- `ocr_text`
- `visual_embedding`
- `vl_caption`
- `vad_segment`
- `speech_text`
- `text_document`
- `subtitle_segment`
- `text_embedding`
- `metadata`

Every evidence record carries all required fields defined by `EvidenceRecord` in `apps/media_archive/v05/rules.py`. Fields that do not apply must be present with `null` or an empty structured value. Image evidence has `hit_time_ms`, `start_time_ms`, and `end_time_ms` set to `null`.

Evidence records are never physically deleted for stale/offline source states. Instead, they must remain auditable with `status = stale` or `status = offline` and `is_active = false`.

## Evidence ID

`evidence_id` is deterministic:

```text
sha256(
  schema_version + "|" +
  file_identity + "|" +
  evidence_type + "|" +
  producer + "|" +
  model_name + "|" +
  model_version + "|" +
  frame_id_or_null + "|" +
  hit_time_ms_or_null + "|" +
  start_time_ms_or_null + "|" +
  end_time_ms_or_null + "|" +
  normalized_payload_key
)
```

It must not use random UUIDs, current time, temporary paths, or non-deterministic payload values.

## File Identity Fallback

File identity priority is fixed:

1. If `content_hash` exists, use `sha256("content:" + content_hash)` and `identity_strategy = content_hash`.
2. If `content_hash` is unavailable and the file is online, use path/stat identity:
   `sha256("pathstat:" + source_root + "|" + normalized_relative_path + "|" + size_bytes + "|" + mtime_ns + "|" + volume_id_or_unknown)`.
3. If the file is offline, reuse `last_seen_file_identity`, set `identity_strategy = last_seen_offline`, `status = offline`, and `is_active = false`.
4. If identity inputs are insufficient, set `status = blocked` and `error_code = insufficient_file_identity`.

## High-Value Frame Selection

V0.5-1 does not run low-cost models. It only consumes fixture or future low-cost evidence summary fields:

- `yoloe_labels`
- `ocr_text`
- `visual_cluster_id`
- `visual_difference_score`
- `embedding_distance`
- `frame_pair_similarity`
- `is_existing_keyframe`
- `timelapse_group_id`
- `fixed_query_hit`
- `fixed_query_score`

The default selection config is in `DEFAULT_FRAME_SELECTION_CONFIG`. The fixed pipeline is:

1. derive `matched_reasons`;
2. compute `high_value_score`;
3. mark below-threshold frames;
4. deduplicate within media by same cluster or explicit `frame_pair_similarity`;
5. apply `min_time_gap_ms`;
6. apply `max_selected_per_media`;
7. apply `max_selected_per_folder`;
8. output `selected_for_qwen_vl`, `selection_reason`, and `excluded_reason`.

Pairwise deduplication only uses explicit fixture `frame_pair_similarity`. It does not infer frame similarity from single-frame `embedding_distance`.

Timelapse groups keep all three frames only when fixture differences are high. If differences are not high, one representative can enter Qwen-VL and the others remain low-cost evidence with `excluded_reason = timelapse_redundant_low_cost_kept`.

## Resource Rules

V0.5-1 defines resource report fields and a pure `evaluate_resource_status` function. Status values are:

- `safe`
- `warning`
- `dangerous`
- `unknown`

Dangerous conditions are evaluated first. Missing fields only produce `unknown` when no known dangerous condition exists. CPU values between the safe and dangerous thresholds, such as 75%, are `warning`.

The concurrency profile configuration defines `safe`, `balanced`, and `aggressive` profiles for visual, audio, and text routes. These profiles are serializable configuration only. V0.5-1 does not implement an automatic dynamic scheduler and does not change worker counts at runtime.

## Folder Batch Rules

Scanning can remain global, but future V0.5 content analysis must run by directory batch. V0.5-1 defines `FolderBatch` and `build_folder_batches` so files are grouped by folder instead of being flattened into a global unordered queue.

Supported folder classifications:

- `video_dominant`
- `image_dominant`
- `audio_dominant`
- `text_dominant`
- `mixed`
- `unsupported_or_empty`

The default `dominant_ratio` is `0.6`. Supported media counts are evaluated in the fixed priority `video > image > audio > text`.

Folder batches include progress fields for future V0.6 UI consumption: current folder, current stage, current file, folder progress, global folder progress, success/fail/skip counts, and resource status.

## Outputs

The high-value frame selector can write fixture outputs to a caller-provided test/run directory:

```text
high_value_frame_candidates.jsonl
high_value_frame_selection_report.json
```

V0.5-1 outputs must not be written into formal V0.1-V0.4 indexes.

## Boundary

V0.5-1 stops after rules and tests. It does not start V0.5-2 and does not run real model inference, 30GB full processing, audio extraction, semantic search, GraphRAG, GUI work, PDF/DOCX parsing, or face identity work.
