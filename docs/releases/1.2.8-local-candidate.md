## 本地 1.2.8 已验证内容

### 通用采访与长内容整理

- 读取已有素材库中的人声转写和视频来源，不重新转写、不读取原视频；
- 将连续碎片按时间整理为长内容段落，提供逐分钟内容、问答线索和代表性原话；
- 区分疑似采访、长口播/长对话、零散语音和全部有转写视频；
- 分类只辅助浏览，不推断人物身份；任何结果都可回到视频和时间码人工核对。

本机只读验证使用一个采访素材库：31 个有转写视频，其中 23 个被标为疑似采访；人物入口返回 11 个分组。数字只说明该次真实库验证结果，不是项目写死的规则，也不是其他用户素材库的性能承诺。

### 功能继承

维护者核对过 1.2.1—1.2.8 的正式、候选和热修复应用包。1.2.8 对外保留搜索、收藏、人物、本地人物管理、文稿选片、剪辑参考、任务管理、重复素材、跨库搜索以及采访/长内容入口。旧诊断脚本和淘汰实验没有作为用户功能继续打包。

### 安装包边界

- Apple Silicon `arm64`，ad-hoc 签名，未使用 Apple Developer ID 公证；
- 应用携带便携 Python 运行环境，不携带模型、数据库、素材和用户配置；
- 原始素材和模型目录保持只读；
- 本机封装时通过了 DMG 校验、应用深度签名检查和只读运行快照。

## 安装版之后发现的选片问题

2026-09-05～09-06 又针对事件级 Excel 剪辑表做了维护验证。维护副本已经能够把测试表正确识别为 6 页、34 个事件，并修复事件边界恢复、日期歧义和部分主体误判；相关集中回归 255 项通过。

但真实候选检查仍发现：

1. “雨后某种作物状态”一类需求仍可能返回其他作物、泛化植物或只命中“雨后/水珠”的画面；
2. “无人物”等否定描述仍可能被错误当成人物证据；
3. 指导表中的内部镜头编号没有可靠映射时，只能报告未解析，不能假装精确定位；
4. 一个事件常需建立、动作、细节、反应和结果等多个镜头，当前每段单主选结构不足；
5. 事件预算可以安全进入 JSON/FCPXML 黑场交接，但不等于实际素材粗剪已经完成。

这些修复仅停留在独立维护构建中，没有覆盖已安装 1.2.8，也没有替换其 DMG。

## 为什么没有发布 v1.2.8

本项目不以“代码写完”作为发布条件。1.2.8 的采访/长内容入口已经通过本机验证，但后续选片维护没有完成真实质量验收；同时公开仓库源码仍以 1.2.7 为一致基线。为了避免源码、安装包和声明互相不一致，本轮只公开状态和路线，不创建标签，不上传 DMG。

准备正式发布前至少需要：

- 将最终源码整理进干净公开工作树并完成隐私审计；
- 解决通用主体、否定和事实边界问题；
- 为事件内多镜头建立明确的数据结构和人工交互；
- 使用跨题材人工 Golden Set 对比旧版与新版候选；
- 回归搜索、人物、收藏、工程保存、JSON 和 FCPXML；
- 重新构建并校验与公开源码内容一致的安装包。

后续优先级见 [`ROADMAP.md`](../ROADMAP.md)。
