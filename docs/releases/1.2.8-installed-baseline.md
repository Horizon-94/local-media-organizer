## 结论

本节点命名为 `v1.2.8-installed-baseline`，而不是伪装成完全可重复构建的正式 `v1.2.8` Release。
它是从安装包中真正携带的源文件反向收口的可追溯开发起点。

1. GitHub 之前的正式源码基线是 `v1.2.7`，包含跨素材库搜索、文稿选片和便携运行环境。
2. 2026-09-03 已安装的 `1.2.8 (128)` 在此基础上加入通用采访/长口播整理。
3. 2026-09-05～09-06 才出现的 V3 事件表导入、主体/否定判断和多镜头候选属于后续维护实验，未进入本 checkpoint。

## 为什么不声明完全可重现

原 APP 从 dirty worktree 构建。构建时的内容摘要覆盖脱敏前源文件，而 APP 内只保留了脱敏后副本。
因此可以证明“这些源文件实际随 APP 运行”，但不能从 APP 单向恢复出当时 dirty worktree
在脱敏前的逐字状态，也不能诚实地声明现在可以构建出与原 DMG 逐字相同的产物。

当前机器还存在独立构建环境限制：Xcode 许可协议未在系统层面接受，
因此本轮不伪造 Swift 重构建成功记录。

## 公开源码规范化

安装 APP 中的合同已被构建器改写为 `$APP_RESOURCES`、`$BUNDLED_PIPELINE_ENVS` 等包内路径。
公开 checkpoint 将该合同恢复为 `$PROJECT_ROOT`、`$ENV_ROOT`、`$MODEL_ROOT` 和工具占位符，
并让两份 `runtime_contract.py` 在源码 checkout 中解析这些通用占位符。
这是发布源码的路径规范化，不改变已安装 APP 对包内路径的解析行为。

## 功能边界

1.2.8 安装版已有能力：

- 图片、视频画面、OCR、人物、人声转写和本地混合搜索；
- 当前素材库/全部登记素材库搜索；
- 收藏、备注和本地人物管理；
- 文稿选片实验、主选/备选、JSON 和 FCPXML 交接；
- 利用既有 ASR 证据整理采访与长口播，不为此重新转写。

## 未纳入内容

- 原始素材、真实 SQLite 数据库、人物名、转写正文和用户收藏；
- 模型权重和本机模型缓存；
- Python 便携运行环境与 APP/DMG 二进制（仍由 GitHub Release 资产单独分发）；
- 安装包内的第三方预编译 DeepFilter 可执行文件；
- 本机日志、token、私人绝对路径、测试输出和缓存；
- 安装日之后的 `event_guide.py` 及相关 V3 事件表维护修改。

## 后续开发起点

不得直接改动 GitHub 稳定基线，且必须保留 Legacy Serial 回退。
