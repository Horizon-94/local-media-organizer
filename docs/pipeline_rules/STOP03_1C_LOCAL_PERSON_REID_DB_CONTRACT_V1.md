# Stop03-1C 本地人物归并数据库合同 V1

## 目标

在不读取原始视频、不上传人脸、不保存额外人脸裁剪图的前提下，对中心
SQLite 中全部可搜索派生画面进行匿名人物归并。输出只表示“可能是同一人物”，
不推断或保存真实姓名。

## 流水线位置

本阶段位于“建立来源与画面去重关系”之后、“准备通用候选数据库合同”之前。
它使用全部可搜索派生视觉单元，不依赖高价值帧数量，也不改变冻结 V25 候选规则。

## 输入

- `visual_units.visual_file` 指向的现有派生图片；
- `source_assets` 中媒体类型为 `image` 或 `video` 且在线的记录；
- 本地只读模型目录中的 `det_10g.onnx` 和 `w600k_r50.onnx`。

禁止将 `source_assets.absolute_path` 作为推理输入。任何派生路径与原始路径相同
的记录必须在 preflight 中拒绝。

## 输出

- 一次运行及每个视觉单元的幂等状态；
- 人脸框、五点关键点、质量分和 512 维归一化匿名向量；
- 匿名人物簇及成员关系；
- 不保存人脸裁剪图片，不修改派生图片和原始素材。

## 通用调度

- 数量全部从中心数据库动态读取，禁止固定输入数或输出数；
- 三路为默认值而不是合同常量；
- 每个 worker 独立 SQLite 连接、独立加载一次模型；
- 领取任务和完成写回使用短事务；
- 推理期间不得持有 SQLite 写事务；
- 已成功的 execution key 不重复推理；
- 中断遗留的 running 项在 resume 时重置为 pending；
- 单项失败不得阻塞其他项。

## 保守聚类

- 同一视觉单元中的两张脸永远不能自动合并；
- 只有相似度达到 `auto_merge_cosine_min` 才自动合并；
- 位于 review 区间的结果只进入人工复核，不自动合并；
- 单张脸允许形成 singleton；
- 聚类采用匿名稳定 ID，不自动命名人物。

## 搜索解释

“戴白色帽子的人”不能只靠人物向量判断：

1. 现有语义通道先找出白色帽子直接命中的画面；
2. 读取画面内匿名人物簇；
3. 再扩展同一人物的其他画面；
4. UI 必须区分“语义直接命中”和“同一人物扩展”。

## 状态

技术 PASS 不等于人物身份策略 PASS。真实模型运行后必须进行跨文件人工复核，
确认误合并率和漏合并率后才能冻结阈值。
