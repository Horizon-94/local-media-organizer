# 图片与视频处理方案合同 V1

状态：`PROFILE_UI_READY / FROZEN_PIPELINE_UNCHANGED / ASYNC_ORCHESTRATOR_PENDING`

## 用户可设置

- 运行方式：自动选择、数据库流水线异步（合同已定义但正式入口尚未开放）、按阶段串行；
- 模型并发路数与抽帧并发路数；
- 视频抽帧间隔 1–10 秒；
- 高价值分析密度：兼容 V25、目标约 15%、20%、30%；
- 图片范围：当前规则筛选或所有图片进入高价值分析。

硬件页只记录芯片、CPU 核数、GPU 核数和统一内存，不记录序列号、设备 UUID 或 UDID。

## 冻结边界

当前 V25 不是固定 15% 上限。它使用每 6 个派生帧一个覆盖锚点，再加入符合条件的高信号补充。
因此“15% / 20% / 30%”属于未来新策略目标，不能回写或冒充 V25。

当前冻结 Step02 视频抽帧间隔为 3 秒。选择其他间隔时，处理方案必须标记
`requires_new_generic_step02_contract_when_changed = true`，在新的通用 Step02 合同完成前不得应用。

所有设置只写应用输出目录中的 `profiles/processing_profile_v1.json`，不写中心数据库。

## 异步交接

`pipeline_async` 表示下游节点可在上游单条结果短事务提交后领取，不等待整个上游阶段结束。正式启用前仍需：

1. 通用任务和 item 状态表合同；
2. 各节点原子领取与幂等 execution key；
3. 资源调度器按内存压力降低并发；
4. 暂停、恢复、失败重试和孤儿进程清理；
5. 小批量真实验收。

## 模型更新闸门

新模型必须依次经过：登记库存与指纹、离线小样本测试、与冻结模型对比、人工复核、明确启用。
应用不得联网下载模型，也不得自动替换正式模型。
