# STOP03-2 V20：内容感知覆盖 + 覆盖层先去重 + V14 补充

## 结论

V20 是对 V19 的大改，不是小参数修改。

V19 的问题：
- V17 覆盖之后，没有先在覆盖层内部做内容去重。
- 合并 V14 后才做最终去重，顺序不够干净。
- 覆盖帧仍然可能落在“灰色平庸帧”上，看不出选择依据。
- 没有真正使用 16×5 分块这种低成本画面内容判断。

V20 的顺序改为：

1. V17 中心向外覆盖锚点。
2. 每个锚点附近 ±2 帧做内容择优。
3. 使用 16×5 luma grid 读取派生帧，做结构/中心/相似判断。
4. 覆盖层先去重。
5. 再加 V14 高信号补充。
6. 最后做单视频最终去重。
7. OCR 继续保持：录屏全进，普通视频只允许明显大字，默认每视频最多 1 帧。

## 最高约束

- 不联网。
- 不下载。
- 不安装依赖。
- 不重跑 YOLOE。
- 不重跑 OpenCLIP。
- 不跑 Qwen-VL。
- 不跑 OCR。
- 不读取原始视频。
- 不写原始素材。
- 只读中心 SQLite。
- 只读 derived visual/frame 文件用于 16×5 grid 与黑帧检查。

## 视觉向量说明

当前 V20 不直接使用 OpenCLIP 向量相似度。

原因：
- 当前 `embeddings` 表在已知结构里主要是 `vector_key`，不确认向量 payload 是否可直接本地读取。
- 不允许为了相似去重重跑 OpenCLIP。
- 所以 V20 先使用：
  - YOLOE label 相似度；
  - 16×5 派生图 luma grid 相似度；
  - 时间距离；
  - 黑帧/尾帧过滤。

后续如果确认本地向量 payload 的实际存储位置，可以单独加入 vector similarity，不应在 V20 里假装已经使用。

## V20 关键规则

### 1. 覆盖锚点

按每个视频 Step02 帧时间排序：

- 从中心帧开始。
- 左右每隔 6 帧设一个覆盖锚点。

### 2. 锚点附近择优

不再盲选锚点本身。

每个锚点检查附近 ±2 帧，优先：

- 非黑帧；
- 非尾部落点；
- 16×5 grid 有结构；
- 中心区域有差异/主体感；
- YOLOE 标签较强；
- 不只是空灰画面。

### 3. 覆盖层先去重

V20 在 V17 覆盖层内部先去重：

- 两个覆盖帧相距 < 18 秒；
- 且 16×5 grid 很相似；
- 或 YOLOE 标签高度相似；
- 则只保留内容分数更好的一个。

### 4. 再加 V14 补充

V14 只作为高信号补充：

- 不黑；
- 不尾部；
- 不录屏；
- 距离覆盖帧至少 15 秒；
- 不重新造成局部扎堆。

### 5. OCR

- 录屏 OCR 保留。
- 普通视频 OCR 只允许明显大字。
- 默认每个普通视频最多 1 帧。
- 弱文字标签只记为 excluded，不进 OCR。

## 验收

PASS：
- 黑帧泄漏 0。
- 录屏进 Qwen-VL 0。
- OCR 不泛滥。
- `v20_anchor_local_best_shift_count` 大于 0，说明锚点附近择优生效。
- `v20_coverage_dedup_drop_count` 有统计。
- 页面上蓝色/紫色/红色帧比 V19 更少落在平庸灰帧区域。

REVIEW：
- V20 仍大量选灰色无标签且视觉平的帧。
- V20 覆盖被去重削得太少。
- V14 补充重新扎堆。

FAIL：
- 黑帧泄漏。
- 录屏进入 Qwen-VL。
- 普通视频 OCR 泛滥。
- 触发联网/下载/模型重跑。
