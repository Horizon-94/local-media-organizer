# 已知问题与修复经验

以下内容从冻结规则、验收文档、测试与 1.1.4 源码中整理，目的是让维护者避免重复踩坑。它不是用户数据、完整内部日志或虚构的 Git 历史。

## 已解决

### 候选规则过宽或覆盖不足

早期候选设计曾出现主体标签过宽、覆盖缺口、尾部补足和重复候选问题。Stop03-2 经过 V1–V25 的设计复核，最终以 V25 合同和数据库快照为准。修复原则是先保存可审计快照，再选择候选，不在旧规则上静默改写。

### “定义了函数”不等于“实际执行”

设计复核中发现过入口存在但主流程没有调用的风险。后来验收要求同时验证命令入口、数据库落库和结果数量，不能只检查函数是否存在。

### 文本搜索没有覆盖全部视觉素材

Stop03-5E V1 的证据覆盖不足以代表完整视觉库。V2 增加 OpenCLIP 全视觉向量覆盖，并保留综合排序证据说明，避免把排序分数误称为识别概率。

### 搜索长时间只有“正在搜索”

1.1.3 虽然搜索可用，但用户无法判断当前阶段、已扫描数量或是否已有候选。1.1.4 增加阶段进度、检查数量、流式候选批次、总用时和暖缓存。

### 取消后后台工作未及时结束

1.1.4 收紧搜索任务取消与子进程状态处理，界面不再把已取消任务继续显示为进行中。

### 本机绝对路径导致换电脑失效

运行合同改用 `$PROJECT_ROOT`、`$ENV_ROOT`、`$MODEL_ROOT` 和工具占位符；通用 DMG 内只保留包内相对位置。发行审计会拒绝真实 `/Users/<name>/...` 路径。

### macOS 干净环境构建失败

- 图标构建需要 Pillow，已加入开发依赖。
- 过大的 SwiftUI 表达式会触发 macOS 14 runner 类型推断问题，搜索页和结果卡片已拆分。
- GitHub Actions 已切换到支持当前运行时的官方 action 版本。

## 仍需注意

- 官方 1.1.4 暂无 Apple Developer ID 签名与公证，Gatekeeper 可能警告。
- 第三方模型不随 DMG 分发，首次使用必须自行下载并核对各自许可证。
- `insightface/buffalo_l` 模型许可与程序 GPL 分离；商业使用前必须向上游确认。
- Python 依赖尚未提供逐包哈希锁，源码可构建功能等价版本，但不能承诺字节级可复现。
- 大规模真实素材验收与单元测试是两种不同证据，不能互相替代。

提交新问题时请使用仓库 Issue 模板，不要附加真实数据库、素材、令牌或完整本机路径。
